# 课记引

对本仓库的 `notes/` 做字面混合检索。融合分过了本项目自己的阈值，并且摘录的字符能对上笔记文件时，打印出处和原文；否则只打印固定拒绝句。

打印出来的是笔记里的一段原文字，不是生成的回答，也不表示这段文字答对了问题。文件核对只检查「这些字是不是该行里的原文」，不是完整的语义依据核验。本项目没有生成步骤，不调用模型，不联网，没有做第 10 课的重排序，不是 RAG 闭环。

## 怎么跑

在项目目录里执行。编写时本机解释器是 Python 3.12.3。只用标准库，不用建虚拟环境，也不用 `pip install`。

```bash
cd projects/keji-cite
python3 -X utf8 -m keji_cite index
python3 -X utf8 -m keji_cite ask "两路原始分不能直接相加"
python3 -X utf8 -m keji_cite ask "明天门票多少钱"
python3 -X utf8 -m keji_cite ask ""
python3 -X utf8 -m keji_cite ask "纳斯达克今天收盘点位"
python3 -X utf8 -m keji_cite ask "游泳池几点开放"
python3 -X utf8 -m unittest tests/test_keji_cite.py -v
```

`index` 读取仓库根目录的 `notes/**/*.md`，把索引写到 `projects/keji-cite/.index/index.json`。这个文件被 `.gitignore` 忽略，换了笔记要重新 index。`calibrate` 会按 `calibration/questions.json` 重算阈值，并覆盖 `calibration/threshold.json` 和 `calibration/record.md`。问句角色是事先写定的，看到分数之后不要删题或改 `k1` / `b`。

空问句可以在没有索引时运行，结果仍是固定拒绝。其他问句没有索引、索引损坏，或阈值文件损坏时，退出码是 2，不会编一句答案。命中和内容上的拒绝都是退出码 0：拒绝是一次成功的判断。

这次命令的标准输出记在 `acceptance/cli-output.txt`。分数和出处以那个文件和 `calibration/record.md` 为准，不在这里另抄一套会过期的期望。

## 为什么这样能跑

1. 终端里的 `python3` 启动解释器。在 `projects/keji-cite/` 下，当前目录会进入模块搜索路径。
2. `python3 -m keji_cite` 执行包里的 `keji_cite/__main__.py`，再调用 `cli.main`。保存文件本身不会运行。
3. 程序从本文件的位置往上找到学习仓根目录，只读那里的 `notes/`。不读 `homework/`，也不跟随指到笔记目录外的符号链接。
4. `chunk.py` 按空行分段。短段整段留下。长段用窗口 80、重叠 20 切开，窗口后半优先停在 `。！？；`。`overlap >= size` 会直接报错，避免窗口不前进。
5. `tokens.py` 丢掉空白和标点，取相邻两个字。中文不按空格分词。「今晚有乐队演出吗」单独 fit 是 7 个二元组，和第 03 课笔记里的 7 维一致。这只说明切词方式对齐，不说明分数会等于课内酒店 FAQ。
6. `embed.py` 对全部切块 fit 一次平滑 idf。查询只能使用这一套 idf，问句里没见过的二元组不加分。权重是「次数 × idf」，再除以向量长度。余弦是两个归一化向量的点积。全 0 向量的余弦定为 0。
7. `bm25.py` 用同一批二元组打关键词分。`k1=1.5`、`b=0.75` 在看分数之前就固定。
8. `formula.py` 先做 `squash = raw / (raw + 2.5)`，再 `融合 = 0.5 × 余弦 + 0.5 × squash`。不把原始分直接相加，不除以这一问的最高分，也不改用两路的 max。两路都是 0 时，压缩还是 0，融合也是 0。
9. 索引把每条切块的编号、原文、字符区间、行号和词频写在一起。读入内存时用保存的 idf 把词频变回向量。参数和当前代码不一致，就当成损坏的索引，要求重建。
10. `ask` 先看问句是不是空白。空白直接拒绝，不去检索。否则打完全部切块，按「融合分从高到低、同分按编号字母序」排序，再和阈值比较。
11. 过线之后还要重新打开笔记：摘录必须等于该文件里记录的那一段，行号也要一致。对不上就整段不输出，改成固定拒绝。这一步只证明摘录没有被改写，不证明它回答了问句。这里不调用模型，也不编「答案是……」。

固定拒绝句沿用第 05 课：「知识库里没有足够依据，不能回答。」

手算例子（不是笔记上的检索分）：余弦 0.20、BM25 原始分 2.5 时，压缩是 `2.5 / 5 = 0.5`，融合是 `0.5 × 0.20 + 0.5 × 0.5 = 0.35`。两路取最大值会是 0.50，那不是本项目的融合。两路都是 0 时融合是 0。

## 这次笔记上的阈值

课程里的 0.30 来自酒店 FAQ，本项目不把它当门槛。`calibration/questions.json` 在查看融合分之前分成校准集、保留集和观察项。`choose_threshold` 只读校准集：

- 最低校准正例严格高于最高校准负例时，阈值取中点。
- 没有这条缝时，阈值取刚好大于最高负例的下一个浮点，校准负例全部过不了线。落在下面的正例记成漏检，不改公式。

对当前这 65 篇笔记、2510 个切块、词表 17299 维，校准命令得到：

- 有缝。最低正例 `cal-pos-self`（自调用不经过代理）融合 0.661525，第一出处是 `notes/java-41-spring-boot.md`。
- 最高负例 `cal-neg-pudding`（芒果布丁怎么做）融合 0.634935。它并不是在回答布丁，而是短标题「本地怎么跑」碰上了「怎么」。
- 中点阈值 **0.648230**（精确值 0.6482300956925275）。五条校准正例都过线，且第一出处落在事先写的文件上。
- 缝宽只有 0.026589。校准集里 BM25 原始分最高到 59.5，`squash` 的 2.5 把它们都压到 0.9 附近，剩下的差别主要在余弦上。没有把 2.5 或 `k1` / `b` 改大。

保留集没有参与定这个数。其中「低分不调用模型」融合 0.616322，第一块已经是 `notes/ai-05-rag-cite-or-refuse.md`，仍低于阈值，所以拒绝。问法不是原文，二元组对不齐。阈值没有为了留下它而放宽。

## 能力边界

字面检索摘录不等于真正回答正确。过线只说明字面融合分够高，并且摘录对得上文件。不能把本项目标成完整语义依据核验，也不能标成 RAG 闭环。

这次跑分里，三件事先就该如实说的事：

- 元讨论会误匹配。问「游泳池几点开放」会命中第 01 课和第 04 课里讨论这句问法的段落。摘录说的是练习该怎么拒绝，不是游泳池的开放时间。字面相同，所以过了 0.648230，但并没有回答开放时间。
- 校准缝很窄。最低正例 0.661525，最高负例 0.634935，缝宽只有 0.026589。最高负例「芒果布丁怎么做」撞上的是短标题「本地怎么跑」。多一个字面碰擦就可能翻到另一侧。
- 保留正例会被误拒。「低分不调用模型」没有参加定阈值，融合 0.616322，第一块已经是 `notes/ai-05-rag-cite-or-refuse.md`，仍低于阈值，命令拒绝。问法不是原文。阈值没有为了留下它而放宽。

另外：

- 「明天门票多少钱」不是两路全 0（笔记里有「多少」），最高融合 0.430218，低于阈值，固定拒绝，不附摘录。
- 「纳斯达克今天收盘点位」两路都是 0，融合是 0。全 0 时排第一的只是编号字母序，回答里不摘录。
- 同义词对不上。换一套笔记、改窗口或改公式之后，0.648230 不能沿用，也不能退回 0.30，要重新 `calibrate`。
- 问句很少。这个中点不是对所有问法最优的分界。
- 短段落碰上少数二元组时，余弦会偏高。这是字面余弦的特性。
