## 复述
- 上一课自己提供接口；这一课用 `httpx` **当调用方**，给请求设等待上限，并规定最多试几次。
- 示例不访问互联网：`MockTransport` 按剧本返回超时、503、404 或 200；`http://example.test` 只是地址文字。
- `httpx.Timeout(0.2)` 是真实连接时的上限；剧本里的超时立刻抛 `ReadTimeout`，不会真等满。
- 重试只覆盖两类：超时且还有次数；状态码 ≥500 且还有次数。404 等同地址通常仍 404，记「不重试」；次数用完仍无 200 →「失败」。
- `try/except TimeoutException` 接住超时继续循环；`finally: client.close()` 成功或异常都关掉客户端。

## 原理（小白话）
- **调用方 vs 提供方**：第10课 FastAPI 等人敲门；第11课 httpx 自己去敲门，还要管「等多久、试几次」。
- **MockTransport**：把真实网络换成本地剧本，handler 每次 `pop` 一项；超时就抛异常，状态码就返回 `Response`。
- **超时是异常、5xx 是响应**：超时走 `except`；503 仍是有 `response`，要看 `status_code` 再决定要不要 `continue`。
- **404 不重试**：地址错了再打同一地址还是错；和「服务暂时忙（5xx）」不一样。
- **`finally` 关客户端**：无论成功返回还是中途异常，连接资源都要收干净。

## 卡点
1. 循环里忘加 `attempt` → 程序一直不结束；`while` 必须有次数上限。
2. 剧本比实际请求短 → `IndexError`（`pop` 空列表）；每一项对应一次 handler 调用。
3. 把 <500 的状态码也放进重试 → 404 又请求一次；应「不重试」。
4. 没有 `except httpx.TimeoutException` → 超时把整个程序打停。
5. `client.close()` 不在 `finally` → 异常路径可能泄漏客户端。
6. 用系统 python → 可能缺 `httpx`；短轨一律 `.venv/bin/python`。
7. ex02 若仍对 503 重试 → 会吃掉剧本里后面的 `200`；修改点是「非 200 一律不重试」。
