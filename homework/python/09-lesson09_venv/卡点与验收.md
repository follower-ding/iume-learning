## 复述
- 虚拟环境（`.venv`）是项目目录里的一份独立解释器 + 独立 `site-packages`；包装进它，不改系统 Python。
- `requirements.txt` 只记**直接依赖**和核对过的版本（`包==版本`）；`#` 行是说明；`pip` 还会装传递依赖，不必手写进文件。
- `.env.example` 只提交变量名和空值；真实密钥写本机 `.env`，且不要进 Git。
- 本课代码只解析**包名 / 变量名**：跳过空行与 `#` 注释；版本符号先切双字符（`==`/`>=`…）再切单字符（`>`/`<`），避免 `httpx=`；等号右边绝不打印。
- 岗位短轨第9课起：用 `.venv` 里的解释器跑；本课练习本身仍只用标准库。

## 跑通命令与输出
本机：Linux，仓库根 = `/workspace/iume-learning`（`demo.py` 的 `Path(__file__).parents[2]`）

```bash
cd /workspace/iume-learning
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python -X utf8 ./python/09-lesson09_venv/demo.py
.venv/bin/python -X utf8 ./python/09-lesson09_venv/practice.py
```

（也可 `source .venv/bin/activate` 后直接 `python`；激活会把 `.venv/bin` 插到 `PATH` 最前。）

## 原理（小白话）
- **为什么要虚拟环境**：系统 Python 是全家共用的厨房；A 项目要 fastapi 0.162、B 项目要别的版本，装进系统会互相踩。`.venv` 是项目自己的小厨房：解释器副本 + 自己的 `site-packages` 货架，装包只落在项目里。
- **解释器**：真正执行 `.py` 的那个程序。`.venv/bin/python` 指向虚拟环境这份；命令前写它（或激活后 `which python` 指向它），才保证用对货架。
- **site-packages**：第三方包安装目录。venv 里是 `.venv/lib/python3.13/site-packages/`；`pip install` 往这里塞 wheel。导入时解释器按 `sys.path` 找，venv 解释器会把自家 site-packages 放进路径。
- **PATH**：终端找命令的目录列表。`source .venv/bin/activate` 把 `.venv/bin` 插到最前，所以敲 `python`/`pip` 会先命中虚拟环境那份；不激活时用完整路径 `.venv/bin/python -m pip ...` 同样安全。
- **解析依赖行**：`splitlines` → 去空白 → 跳过空/`#` → 按版本符号切开取左边包名 → 方括号前截断。双字符符号必须先于单字符，否则 `>=` 被 `>` 先切开会留下 `=`。

## 卡点
1. 用系统 `python3` 跑后面课 → `ModuleNotFoundError`；短轨改用 `.venv` 解释器并先 `pip install -r requirements.txt`。
2. 裸跑 `pip install` 可能装进系统；要用 `.venv/bin/python -m pip install ...`。
3. 版本符号先切了单个 `>` → 包名变成 `httpx=`；双字符符号要排在前面。
4. 打印了等号右边 → 输出出现密钥/占位值；只取 `split("=", 1)[0]`。
5. 把 `.env` 或 `.venv` 提交进 Git → 密钥泄漏 / 仓库膨胀；只提交 `.env.example`，忽略规则已含二者。
6. 本地路径：本工作区课文件在 `python/09-lesson09_venv/`，`parents[2]` 落到 `/workspace/iume-learning`，故 `requirements.txt` / `.env.example` / `.venv` 放在该根（对应讲义「仓库根」）。
