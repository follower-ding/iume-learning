# AI Lab 第01课验收（iume）

时间：2026-11-10 Asia/Shanghai

## 复述
- 本课只做一件事：把一组带角色的消息交给客户端，拿回一段文本。
- 角色分清：`system` 放整场都要遵守的规则，`user` 放客人这一问，`assistant` 是模型已说过的话，`tool` 留给后面课（工具执行结果写回）。
- 调用方只依赖 `complete(messages)`；练习构造的是 `MockChatClient`，模型名 `mock-hotel-front-desk`。
- Mock 按关键词从 `hotel_faq.json` 抄一句；抄不到就说「只准备了……」，不编游泳池/接送/价格。
- 打印的 token 是估算（中文约一字一、其余约四字一），不是账单；真实计数在接口 `usage` 里。
- 练习不读 `.env`、不联网；密钥不进源码。

## 原理（小白话）
- **消息列表**：一次调用不是揉成一坨字符串，而是按 role 分开；后面才能把工具结果和客人话拆开。
- **同一套 `complete`**：Mock 和真实兼容客户端方法签名一样；练习换客户端只改构造几行，后面打印不用跟着改。
- **Mock 是脚本**：读关键词抄 FAQ，不是理解语义；没有的句子就不该现编——这是后面排错的底线。
- **估算 token**：课堂观察用；对账看真实响应的 `usage`。
- **密钥**：只在环境变量/本地 `.env`；异常里的 `sk-...` / `Bearer ...` 样式会被抹成 `[redacted]`。

## 口头自查（自己答）
1. `system` 约束整场规则，`user` 是这一问。整份规章塞进 `user`、客人问题塞进 `system`，调用方就分不清「规矩」和「提问」，后面拼工具结果也会乱。
2. 本课打印的 token **不能**拿去对账；真实计数读响应里的 `usage`（`prompt_tokens` / `completion_tokens`）。
3. 换成 `OpenAICompatibleClient`：改构造（base_url / api_key / model 等）；`complete` 之后的打印不用改。

## 卡点
1. 把 Mock 当真模型 → 游泳池等没有 FAQ 的题它必须回「只准备了……」，不是编答案。
2. 用估算 token 对账 → 只看 `usage`。
3. 角色揉成一条字符串 → 后面工具课分不开。
4. 密钥写进源码或提交 `.env` → 禁止；练习默认不读密钥。
5. 用系统 python → 可能没有 `ailab`；一律 `.venv/bin/python`（本课已 editable 安装 lab）。
