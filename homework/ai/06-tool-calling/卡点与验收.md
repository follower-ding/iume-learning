## 原理（小白话）
- **为什么金额必须由工具算**：模型在 arguments / final 里写「合计 60」只是又一次自由生成；单价在代码常量 `HOURLY_RATE=30`，只有函数跑出来才可信。
- **为什么没小时数要 final 反问、不默认 1**：规章没有默认时长；猜 1 会算出无人要求的价格，评测会判失败。
- **为什么 shell 能解析却不执行**：先解析 JSON、再对照允许列表。名字可以出现在模型输出里，但不在 `hotel_tools()` 字典 → 拒绝，不进 shell/SQL/路径。
- **为什么 bool 要单独拒**：Python 里 `True` 是 `int` 子类，`isinstance(True, int)` 为真；不挡会把 True 当成 1 计价。
- **本课没有循环**：只演示「提出调用 → 代码执行允许工具」；重复调用、未知工具停机留给第07课 `run_agent`。

## 口头自查（自己答）
1. 合计必须由 `quote_late_checkout` 算：模型写在 arguments 里的数字不可信，单价只在工具常量里。
2. 没写小时数输出 final 反问：不默认 1，避免算出无人要求的价格。
3. 模型输出 `shell`：本课解析成功后对照允许列表 → 拒绝，没有被执行。

## 卡点
1. 让模型在 JSON 里自己填「合计 60 元」→ 那不是工具，只是自由生成。
2. 把模型给出的字符串交给 shell / SQL / 文件路径 → 本课两只工具都没有这些能力。
3. 参数不合法直接崩溃、客人只看到栈回溯 → 应抛 `ToolArgumentError`（下节写回消息）。
4. 小时数缺省时默认 1 → 「看起来能跑」但评测失败。
5. 信任 `isinstance(x, int)` 而不拒 bool → True 被当成 1 小时。
6. 以为解析成功等于可以执行 → 允许列表才是执行门闩。

exercise / probe_no_hours / probe_allowlist / probe_bad_hours / probe_price_from_tool 与 cases 一致；概念（工具算价、缺小时反问、允许列表、bool 拒）敢讲一层。→ **可标【过】**（待主代理/知微确认）。**未发知白台**（本轮只做本地交付）。
