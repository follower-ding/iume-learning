## 复述
- 本课只做一件事：让模型（或 Mock）只交一个 JSON 对象，意图必须落在允许列表。
- 形状：`{"intent":"...","question":"客人原话"}`；`intent` 只能是 `check_in` / `check_out` / `breakfast` / `parking` / `pets` / `wifi` / `cancel` / `unknown`。
- 提取：先去 ```json 围栏，再从第一个 `{` 括号配对（字符串里的括号不算），然后 `json.loads`；**绝不 `eval`**。
- 字段不合法（列表外意图、空 question、非对象）= 解析失败，不带着残缺数据往下走；`swim` 和「根本不是 JSON」一样处理。
- `classify_intent` 最多调两次：第一次失败就把刚才的原文放进 `assistant`，再追加「只输出一个 JSON 对象」；第二次仍失败抛 `JsonExtractError`。
- Mock 关键词顺序：`取消` 排在 `入住` 前，所以「入住日前可以取消吗」归 `cancel`——这是脚本规则，不是 NLU。

## 原理（小白话）
- **为什么 JSON**：自由文本不好分支；结构化意图才能接到后面的工具/检索课。
- **括号配对 + loads**：外面可以有说明或围栏；只取第一个完整对象。模型输出是不受信任文本，`eval` 会当代码跑——禁。
- **代码再查允许列表**：提示里写了列表不够，模型会忽略；`swim` 当解析失败再要一次，不悄悄收成 `unknown`。
- **修复轮带回原文**：模型才知道你拒绝的是哪一段；最多再调一次，防坏输出死循环。
- **Mock 关键词顺序有意**：取消优先于入住，练习才稳定；别当真语义理解。

## 口头自查（自己答）
1. 用 `json.loads` 不用 `eval`：模型输出不受信任，`eval` 会执行任意代码。
2. 先写解释再给 JSON 时：修复轮把失败原文放进 `assistant`，再追加「只输出一个 JSON」；最多再调用 **1** 次（总共 2）。
3. `intent=swim`：当成解析失败再要一次，**不**悄悄收成 `unknown`。

## 卡点
1. 用 `eval` 解析模型输出 → 安全坑，一律 `json.loads`。
2. 解析失败就猜意图继续走 → 后面工具/检索会跟错；应失败或再要一次。
3. 修复轮不把失败原文发回去 → 模型不知道拒的是哪段。
4. 允许列表只写在提示里、代码不查 → 提示会被忽略；`swim` 必须当失败。
5. 把 Mock 关键词顺序当真 NLU → 「取消优先入住」是脚本规则。
6. 无限重试 → 坏输出打转；硬上限 2 次。
