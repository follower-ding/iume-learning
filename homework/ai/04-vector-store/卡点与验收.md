## 复述
- 向量本身不能当答案。库把稳定 id、原文、向量、少量 metadata 放在同一条记录里，按余弦取出最接近的几条。
- `MemoryVectorStore.add` 记四样：`id`（引用用）、`text`（给人/模型读的原文）、`vector`（同一次 fit 的 TF-IDF）、`metadata`（至少 `source_id`/`title`）。
- 短问答标题只参加向量（`document_text = title\ntext`），入库原文只留正文，避免引用时把标题再贴一遍。
- 搜索对每条算余弦，按分数从高到低；分数相同按 id 字母序，所以全 0 时顺序固定，不表示谁更相关。
- 维度不一致抛 `VectorDimensionError`（不截断、不补零）；重复 id 拒写，避免静默覆盖。换嵌入模型要整库重算。
- top-k 里可以有很低的分数；删不删留给下一课阈值（`DEFAULT_MIN_SCORE=0.2`）。

## 原理（小白话）
- **为什么 id+原文+向量一起存**：下一课要引用原文、核对正文；只留向量没法写出处。
- **为什么标题进向量、正文进库**：检索时标题关键词有用；引用时别把标题再贴一遍。
- **为什么维度拒、重复拒**：不同空间的数不能比；静默覆盖会让引用指向另一段正文。换模型→整库重算。
- **为什么全 0 仍有固定顺序**：排序键是 `(-score, id)`；字母序是稳定输出，不是相关度。
- **为什么 k 别太小就当事**：k=1 干净，但看不见第二名差多远；低分邻居要留给阈值，不是检索自己删。

## 口头自查（自己答）
1. 一条记录要同时留 id、原文、向量：只留向量，下一课做不出引用，也无法核对正文。
2. 游泳池分数都是 0，顺序仍固定（按 id 字母序）；这不表示早餐更相关。
3. 维度不一致应报错，不截断不补零；换模型后旧向量整库重算，不能只重算新问题。

## 卡点
1. 只存向量，不存原文和 id → 下一课无法引用/核对。
2. 把 top-k 低分当成「相关」→ 相关与否要有阈值（第05课）。
3. 查询用另一套向量空间或维度不同还硬比 → 库会抛 `VectorDimensionError`。
4. 相同分数的字母序被读成相关度 → 全 0 时只是 id 序。
5. 重复 id 静默覆盖 → 本课直接拒写。
6. 把 k 改成 1 当「过滤低分」→ 其实只是少看几行，阈值还没上场。

## 结论
exercise / probe_k1 / probe_reject / probe_tie_break 与 cases 一致；概念（同条四字段、维度拒、平分字母序、低分留给阈值）敢讲一层。→ **可标【过】**（待主代理/知微确认）。**未发知白台**（本轮只做本地交付）。
