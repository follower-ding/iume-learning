## 复述
- 检索不是把库里的话都交给模型。`RagPipeline.answer` 固定顺序：嵌入问题 → top-k → 丢掉 `score < DEFAULT_MIN_SCORE(0.2)` 的命中 → 有强命中才 `complete` → 检查草稿里的 `[faq-...]`。
- 一条都不剩：返回固定拒绝语「知识库里没有足够依据，不能回答。」，`reason=low_score`，**不调用模型**。
- 引用必须落在「这一次过了门槛的 id」上。没有引用 → `missing_citation`；出现不在允许集合里的 id → `unknown_citation`。两种都改成同一句拒绝，草稿不留。
- 0.2 只对当前短问答 + `TfidfEmbedder` 有意义。入住真问约 0.28–0.40；游泳池/机场接送是 0；「我什么时候能进房间」约 0.23，擦着门槛。换资料或换嵌入要重看分数。
- Mock 只会复述提示里第一条资料并带上它的 id。过线常常只有第一条，所以输出看起来很稳——这是管道被固定住了，不是模型学会了挑选。

## 原理（小白话）
- **为什么低分不调模型**：检索空了还调，模型就会用对话常识补时间/价格；门槛把「不够依据」挡在生成之前。
- **为什么草稿整段作废**：半句假话一旦拼进最终回答就出去了；失败分支只留固定拒绝语。
- **为什么只允许「过了门槛」的 id**：允许低分 id 等于没有门槛；允许未检索到的 id，模型可以瞎编出处。
- **为什么 0.2 不是通用常数**：它卡在当前字面向量的缝上；换嵌入/换资料，相关最高分与无关分都会动，要重标定。
- **为什么延迟退房不说 30 元**：规章只说「先问前台有没有空房」；单价在第06课工具里，本课检索路径只能复述规章。

## 口头自查（自己答）
1. 最高分低于门槛时不再调用模型：避免用常识补时间/价格；`reason=low_score`，只回固定拒绝语。
2. 草稿写了 `[faq-pool]`：id 不在本次过线集合 → `unknown_citation`，整段作废，连「全天开放」也不留。
3. 「延迟退房怎么收费」走检索：只复述「先问前台」，不能补 30 元；单价留给工具课。

## 卡点
1. 检索为空仍调用模型 → 常识补时间/价格。
2. 引用检查失败后仍把草稿和拒绝语拼在一起 → 半句假话已出去。
3. 允许引用分很低、没过门槛的 id → 等于没有门槛。
4. 用 Mock「总是复述第一条」证明整条链路会推理 → 它只证明引用格式和拒绝分支。
5. 把 0.2 当成永远通用的阈值 → 换资料/换嵌入要重看分数。
6. 延迟退房补出单价 → 本课只有规章，没有报价工具。
